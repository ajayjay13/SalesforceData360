Harmonization and Unification

Mapping source data to the data model, keys and cardinality, then identity resolution to build one unified profile per person.

  • Define the purpose, process, and supported use cases of unification.
  • Model data in Data 360.

Bronze, silver, gold

  1. Data stream / DSOraw, as-is
  2. DLOschema enforced, stored
  3. DMOharmonized, used by IR, insights, segments

DSO is the original (CSV, JSON, parquet). DLOs are stored as Parquet. DMOs are views over DLOs or materialized objects such as Unified Individual.

Harmonization versus unification

Harmonization

  • Bringing disparate data into one model
  • Data model, keys, cardinality
  • DMOs, data mapping
  • Check with Data Explorer

Unification

  • Identity resolution
  • Key ring, the Unified Individual
  • Rulesets, match rules, reconciliation rules
  • Check with consolidation rate and Profile Explorer

Without harmonization you cannot unify.

Which data model

Standard (Customer 360)

  • Opinionated, canonical
  • Fits most use cases
  • Some objects are required for identity resolution
  • Default mappings for Salesforce clouds
  • AppExchange offerings build on it

Custom

  • Matches an in-house model
  • Familiar to your team
  • You maintain it, not extensible by Salesforce

Hybrid

  • Standard plus custom attributes and custom DMOs only if one does not exist
  • Best of both worlds

Objects that make unification and activation work

  • Individual

    The person. Required for all Profile-category data.

  • Party Identification

    Third-party identifiers for an individual.

  • Contact Point objects

    Email, Phone, Address, App, Social. Map at least one channel for unification and activation. Linked to Individual through the Party attribute.

  • Subject areas

    Party, Product, Sales Order, Engagement, Case, Privacy, Loyalty. Party covers any organization, individual or member.

Keys and cardinality

  • Primary key

    Required on every DMO, unique, cannot change. You cannot save a mapping without it. It comes from the source or a formula. A DMO primary key is not the DLO primary key.

  • Foreign key

    Links a DMO to another, for example a contact point to Individual.

  • Cardinality

    1:1 or N:1, set when you create the relationship, cannot be changed. Many contact points to one individual, many sales orders to one individual.

  • Counting keys

    One flat row with an Individual ID, 2 emails, 2 addresses, 2 phones needs 6 extra formula fields for contact point keys, for example CONCAT(Individual ID, "_Email_Work"), and transforms for 1:N shaping.

Normalized versus denormalized

Normalized (Data 360 model)

  • Many tables, joins
  • Less redundancy, better integrity
  • Harder to query

Denormalized (one wide table)

  • Faster reads
  • Redundancy and sync risk
  • Spreadsheet format

Mapping workflow

  1. Inventorydata dictionary for every source
  2. Inspectfield-level quality and category
  3. Mapstandard or custom DMOs
  4. Relatereview and add relationships

Design phase first. Pushing buttons is easy, so spend more time in design.

Identity resolution

  • Ruleset

    Groups match and reconciliation rules. Several allowed, such as B2C and B2B. Runs about every 24 hours by default.

  • Match rules

    Defaults: fuzzy name with normalized email, phone or address, and fuzzy name with phone and email. Custom rules on profile data are possible.

  • Overgrouping and undergrouping

    Loose rules overgroup. Strict rules undergroup. Better to undergroup than overgroup.

  • Reconciliation rules

    Source priority, most recent, most frequent.

  • Output

    Unified Individual plus Unified Link Individual entries (a shared UUID per key ring). Full lineage kept, nothing deleted or merged.

  • Validate

    Consolidation rate, processing history, Profile Explorer.

Watch for these

  • Profile Explorer shows the unified view built through a Lightning record page. It can include Calculated Insights.
  • Plan with the end in mind: IR, calculated insights and segments all depend on how you map and relate.
  • Individual-level questions on the exam: Party subject area, Contact Point Phone for a custom phone object, many-to-one for contact point to Individual.
