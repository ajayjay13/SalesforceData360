Data 360 Setup and Administration

Provisioning, permission sets, org-wide settings, governance tools, consent and data subject requests, sandboxes, and troubleshooting.

  • Configure Data 360 permissions, permission sets, and organization-wide settings.
  • Apply data governance requirements to platform configuration.
  • Manage the development lifecycle with available tooling.
  • Use tooling to diagnose and troubleshoot common issues.

Where to provision Data 360

Existing org as home org

  • Simplest path, CRM data already there
  • Immediate access to Sales, Service, Marketing data
  • No extra integration
  • Fewer licenses to manage
  • May inherit governance and tech debt
  • Location may not match enterprise residency needs
  • Multiple orgs risk fragmentation unless paired with Data Cloud One

New dedicated org

  • Clean slate for governance
  • Central control across lines of business
  • Choose region for compliance
  • Neutral shared service org
  • Needs a new org license and companion connection
  • More admin overhead, slower time to value
  • Fits a Data Cloud One home org with companions

Auto-provisioning: products like Agentforce and Agentforce for Marketing can add Data 360 licenses. Companion orgs get a different license than the standard one. Provision carefully.

Data Cloud One

  1. Connectcompanion orgs to the home org
  2. Sharea data space with them
  3. Grantusers access to shared objects
  4. Buildinsights, segments, prompts, flows

Companion org SKU is $0. Metadata of the shared data space (DMOs, calculated insights, segments) is synced to connected orgs. Use cases: cross-selling, 360 view, combined forecasting, cross-org analytics.

Permission sets and profiles

Permission sets

  • Govern access to Data 360 capabilities
  • Exam focuses here
  • Do not include CRM reports and dashboards

Profiles

  • Identity User profiles let people into Data 360
  • Want broader access? Use a higher profile such as System Administrator

Org-wide settings

  • Object permissions

    Enable View All and Read All on the CRM objects Data 360 should connect to. Review them in the Data Cloud Salesforce Connector permission set.

  • Default time zone

    Dates and times are stored in UTC and displayed in the user's zone, defaulting to the org-wide default. Date and time segment filters use the org-wide default.

  • Feature Manager

    View and enable beta features. Betas are not covered on the exam.

Governance toolkit

  • Data spaces

    Logical partitions for brands, regions, departments. Add DLOs, then filter on non-key qualifier text fields. Filters apply at query time, so row counts are off. Not a residency tool. Use when brands need separate data and processes. Not the answer when cross-brand unification is the point.

  • Tagging and classification

    Tag fields (such as PII), classify (confidential, internal, public), propagate to DMOs and calculated insights, then attach policies. Benefit: rules apply to groups of fields consistently.

  • Policies

    Access policies and purpose policies, plus dynamic data masking policies. Example: an agency sees part of a report while managers see everything.

  • Security

    Platform Encryption with customer-managed keys. Private Connect for a private link between Data 360 and sources, including Zero Copy.

Consent and data subject rights

  • Privacy data model

    Consent attaches to the Individual DMO, one Individual to many consent preferences. Layers: global, engagement channel, contact point, data use purpose, brand.

  • ShouldForget

    Right to be forgotten. Permanently deletes PII and related contact point records.

  • Processing

    Restricts Data 360 processes such as segmentation, insights and queries from using the data. Data stays.

  • Portability

    Lets the customer export their Data 360 data.

  • How deletion behaves

    Deletes the Individual and the contact point records linked to it through the Party field. It does not remove data from other DLOs. Requests are processed again at 30, 60 and 90 days. Submit separately for each connected Salesforce cloud (as stated in the bootcamp slide).

Sandbox to production

  1. Create or matchsandbox from a production org with a Data 360 SKU
  2. ProvisionGet Started in Data 360 Setup
  3. Hydratere-authenticate connections, ingest data
  4. DeployData Kit via Change Sets or DevOps Center

The sandbox keeps configuration but not authentication or data. Usage draws from production credits at lower multipliers and shows in Digital Wallet.

Diagnose and watch

  • Problem Records DLO (PR_)

    Query it like any table. Shows which records failed, why (for example invalid date format) and when. Appended on every stream run. Refresh History has a Problem Records metric.

  • Validation tools

    Data Explorer and Profile Explorer, DLO and DMO preview, Query Editor (ANSI SQL on any DLO, DMO or Calculated Insight).

  • Events

    Platform events notify. Change Data Capture syncs data. Data Cloud-triggered flows act on Data 360 updates.

  • Workflow orchestration

    Chain ingestion, batch transforms, identity resolution and calculated insights in order. Watch credit use.

  • Agentforce observability

    Session tracing and audit feedback show how agents used data. Data masking is disabled for Agentforce, per the slide.

Watch for these

  • Dedicated sandbox is worth it for parallel development streams, complex projects, complex configurations.
  • Failed ingestion alert: record-triggered flow on the data stream record, not a scheduled poll.
  • Beta features from Feature Manager are not on the exam.
