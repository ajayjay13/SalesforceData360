Data Activations and Utilization

Segments, activations, enrichments, data actions, clean rooms, and using Data 360 inside Salesforce Flows.

  • Define basic concepts of segmentation and use cases.
  • Manage segments within Data 360.
  • Publish Activations within Data 360.
  • Act on data.

Segmentation versus activation

Segment: who or what

  • Queries that find an audience by shared traits
  • Output: a list of unique IDs, usually Unified Individual IDs
  • Based on Profile or Engagement data

Activation: where and with what

  • Publishes a segment, DMO or flow call to a target
  • Output: JSON payload of IDs and attributes

Segments

  • Four types

    Standard, Waterfall, Real-Time, Dynamic.

  • Segment on

    Profile data means the population is people. Engagement data means the population is events.

  • Direct and related

    Direct (1:1) attributes have one value per record. Related (N:1) can have many. Use containers for related attributes so conditions apply to the same record.

  • Lookback window

    How many days of engagement history the segment scans.

  • Publish schedules

    Standard: every 12 or 24 hours. Rapid: every 1 or 4 hours, only for Marketing Cloud Engagement and file storage, 7-day engagement limit, max 20 per org.

  • Membership

    Stored in Latest and History DMOs for the segmented DMO.

Activations

  • Targets

    Salesforce (MCE, MCP, B2C, Loyalty, Data 360), file storage (S3, GCP, Azure, SFTP), external platforms (ads, analytics).

  • Four types

    Segment activation, DMO activation, API activation, activation template.

  • Limits

    25 values per related attribute. 300 related attributes per activation. 8 DMOs per activation. 10,000 activations with related attributes.

  • Schedule

    Segment activations follow the segment schedule. DMO activations are manual only. API activations refresh every 24 hours.

  • Extras

    Filter, limit and rank records. 90-day lookback.

  • Membership

    Stored in Activation Audience Latest and History DMOs.

Enrichments into CRM

Related List

  • Surface many DMO records
  • MCE email engagement, web engagement from the SDK
  • Unified Individual related lists on Account, Contact, Lead
  • Direct-DMO related lists on objects like Case, Order, Opportunity

Copy Field

  • Copy one value from Data 360
  • A Calculated Insight such as CLV (single dimension)
  • Loyalty tier from a partner
  • Onto Account, Contact, Lead, Case, Opportunity, custom objects and more

Data actions versus activations

Data actions

  • Event-driven alerts and triggers
  • Near real time to sub-second
  • CRM, Marketing Cloud Journeys, external platforms

Activations

  • Publish whole segments
  • Batch
  • Marketing Cloud, DSPs, file storage

Clean rooms

Good fit

  • Active partner ecosystems: retailers, publishers, travel
  • Co-marketing allies
  • Segment overlap without exposing PII

Poor fit

  • Individual-level personalization
  • Real-time message triggers
  • Very granular segments (about 100 minimum matched)
  • Partners with weak regulation or different intent

Providers host the collaboration (Data 360 or AWS). Consumers share their audience against provider data. Outcome: audience insight, not sharing PII.

Flows with Data 360

Activation-triggeredExtends batch activation to any system. Needs activation target, segment, activation, MuleSoft connector or external service. Pick an action group.
Platform event-triggeredSubscribe to batch data transform events instead of schedules.
Record-triggered monitoringWatch data streams, identity resolution, calculated insights, segments, activations for status, rows and errors.
Agentforce with flowsGet DMO records, get data graphs, call retrievers, run flow actions.

Watch for these

  • Need a CRM formula on a Data 360 value? Copy Field enrichment.
  • Data graph is not a prerequisite for Marketing Cloud data actions.
  • Clean room overlap analysis gives audience insight. It never shares PII.
